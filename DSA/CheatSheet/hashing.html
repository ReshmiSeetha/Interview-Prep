Hashing & Hash Tables

Use hashing when you need fast lookup, duplicate detection, frequency counting, grouping, or complement search. Think in keys, buckets, collisions, and O(1) average access.

Insert O(1) avg Search O(1) avg Delete O(1) avg Worst case O(n) Space tradeoff

What it is

  • Hashing maps a key to an index.
  • Hash table stores key-value pairs in buckets.
  • Goal: fast access with even distribution.

How it works

Key → Hash function → Bucket index → Collision handling

Use it for

  • Duplicates / seen before
  • Frequency counting
  • Two Sum / complements
  • Grouping by signature
  • Prefix sum lookups

Map vs Set

HashMap
key → value, counts, indices, groups
HashSet
unique values, membership checks

Collision handling

  • Separate chaining: list/tree inside bucket.
  • Open addressing: probe for next slot.
  • Linear probing, quadratic probing, double hashing.
  • Rehash when load factor gets too high.

Common interview patterns

  • Two Sum
  • Valid Anagram
  • Group Anagrams
  • Contains Duplicate
  • Subarray Sum Equals K
  • Longest Consecutive Sequence
  • Valid Sudoku

Java essentials

Map<Integer, Integer> map = new HashMap<>();
Set<Integer> set = new HashSet<>();

map.put(key, value);
map.getOrDefault(key, 0);
map.containsKey(key);

set.add(x);
set.contains(x);
set.remove(x);

When not to use hashing

  • Need sorted order or traversal by order.
  • Need range queries like min/max in interval.
  • Need predecessor / successor queries.
  • Need deterministic ordering by key.

Pitfalls

  • Bad hash distribution.
  • Too many collisions.
  • Mutable keys.
  • Assuming O(1) worst case.

Quick mental rule

Need fast lookup / counting / grouping?
→ Use HashMap or HashSet.

Need sorted order / range queries?
→ Use tree / ordered structure instead.
